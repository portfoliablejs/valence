# `ds-player-view`

The `ds-player-view` component is a **stateless (presentational)** Template that composes `ds-header`, `ds-thumbnail`, `ds-seek-bar`, `ds-video-controls`, and `ds-subtitle` into a single video-first viewport surface.

---

## Principles

### Stateful Host, Stateless Template
The template follows **State In / Controlled Playback**:
* **State In (Attributes / Properties):** The host controls media sources, playback defaults, layout sizing, and UI visibility requests.
* **Internal Playback Sync:** The template maps the configured video source into `ds-thumbnail`, synchronizes duration and progress into `ds-seek-bar`, and keeps `ds-video-controls` aligned with the live video element.
* **No Smart Routing Logic:** Route switching, data fetching, analytics, and page transitions remain outside this template.

### Composition Boundary
`ds-player-view` provides structure, not media ownership:
* **Top Timeline Region:** A viewport-pinned `ds-seek-bar` using `variant="top-bar"` that controls and displays playback progress.
* **Header Region:** A full-bleed `ds-header` rendered at the same top viewport position used by CaseView/HomeView, with breadcrumb and accessibility menu visible.
* **Media Region:** A centered `ds-thumbnail` that renders the video inside the device frame using `screen-video` only.
* **Media Source Fallback:** The thumbnail accepts the host-provided `video-src` value and retries local template asset paths when the root `/src/content/...` URL is not served in the current runtime. This mirrors the audio player fallback pattern.
* **Subtitle Source Fallback:** The caption overlay accepts the host-provided `subtitle-src` value and retries the matching local template asset path when a root `/src/content/...` VTT URL is not available at runtime.
* **Visibility Ownership:** The template emits `ds-player-ui-visibility-change` requests and the host app owns the `ui-hidden` attribute that actually hides or reveals the player UI shell.
* **Return-Only Hidden Mode:** When `ui-hidden` is active, host applications can keep header visibility while reducing breadcrumb context to only the return/back affordance.
* **Control Region:** A compact `ds-video-controls` cluster that drives play, pause, mute, speed, stop, and captions against the same video node.
* **Caption Region:** A `ds-subtitle` overlay that becomes visible when caption text is available.
* **Caption Rule:** If no subtitle source is configured, the CC control is hidden entirely so the UI matches the available media.

## Accessibility & Semantics

* **Semantic Landmark:** Renders a top-level `<section>` with host-provided `aria-label` for player context.
* **Keyboard and Tooltip Semantics:** Delegated to composed children (`ds-seek-bar`, `ds-video-controls`, and `ds-subtitle`).
* **Reduced Motion Strategy:** The template does not impose route transitions internally, enabling host shells to centralize reduced-motion handling for surrounding layouts.
* **Viewport Containment:** The shell remains `100dvh`-bounded so layout tuning does not force scroll.
